# 公开 npm 发布规划（适配器 0.18.1 / 平台 0.7.2）

## 1. 发布形态

两个公开 npm 包，平台先发：

| 包 | 版本 | 角色 | pi.dev/packages |
|---|---|---|---|
| `pigroups` | `0.7.2` | 平台 server，npm 依赖 | 不列出（不是 Pi package） |
| `pigroups-adapter-pi` | `0.18.1` | Pi extension + skills | 通过 `pi-package` keyword 检索 |

适配器对平台使用**精确依赖**：

```json
"dependencies": { "pigroups": "0.7.2" }
```

平台包暴露 `./package.json` 和 `src/main.ts`；适配器从已安装的 `pigroups` 包解析平台目录，
`PIGROUPS_PLATFORM_DIR` 仍可用于指定外部 checkout。

## 2. 平台版本检测（硬锁，不保留兼容层）

版本对是唯一的：适配器 `0.18.1` 只接受平台 `0.7.2`。旧平台不是“警告后继续”，而是失败。

四个检查点：

1. **npm 依赖**：`package.json` 的 `dependencies.pigroups` 精确写 `0.7.2`，不写 `^`。
2. **启动 checkout 预检**：`startOrg` 在 spawn 平台之前读 `<platformDir>/package.json`；
   版本不是 `0.7.2` 就报错，不启动、不迁移数据。
3. **health / reattach 检查**：新启动、duplicate 重接、已有组织重接，`/v1/health.version`
   必须是 `0.7.2`；不是就停掉本次刚拉起的进程（如果有），保留旧平台和记录，报错让人重启。
4. **attach 检查**：`AdapterLoop.init()` 的 `whoami.server.version` 必须是 `0.7.2`；
   不是则不进入 ready、不轮询、不投递，错误里写清适配器版本、平台版本和修复命令。

单一来源：

```ts
export const ADAPTER_VERSION = '0.18.1';
export const EXPECTED_PLATFORM_VERSION = '0.7.2';
```

`test/version.test.ts` 断言 `package.json` 版本和平台依赖；`test/platform-version.test.ts`
覆盖预检、health、whoami 三种不匹配和匹配成功；`pg_whoami` 同时报告
`expected_platform_version`，方便现场判断。

**不保留向后兼容**：

- 删除 `SUPPORTED_PLATFORM_MINORS`、`platformCompatibilityWarning`、`platformMajorMinor`；
- 删除 `platformSupportsHeartbeat` 与 0.4/0.5 的 heartbeat fallback（0.7.2 永远支持心跳）；
- 删除 0.4/0.5/0.6 兼容测试；旧平台由精确检查拒绝；
- 旧 live 平台不会被自动杀掉或热升级。用户必须用新版本重启平台；root 在平台不可达时
  可以通过 `ensurePlatform` 用已安装的 0.7.2 启动。

## 3. 文档与注入提示词

- 删除 `docs/handoff.md`、`docs/handoff-quant-analysis.md` 及所有引用；不再作为发布内容。
- `docs/` 保留设计说明、概念稿、发布规划和修改说明；公开包只包含用户文档，排除内部交接。
- **所有模型会看到的注入提示词改为英文**：
  - `src/extension.ts` 的工具描述/参数描述（当前已是英文，审计后保持）；
  - `src/loop.ts` 的注入行（spawn/repair/control/scheduled/gap/401 等）；
  - `skills/pigroups-message/SKILL.md`、`skills/pigroups-org/SKILL.md` 全文英文。
- 代码注释、README、设计文档可继续中文；由维护者按读者选择。

## 4. 包与发布工程

### 适配器

- `private: false`，统一 license，版本 `0.18.0`；
- 依赖 `pigroups: "0.7.2"`；
- `files` 只含 `src`、`skills`、`README.md`、`CHANGELOG.md`、`LICENSE`、用户文档；
- `pi` manifest、`pi-package` keyword、README 安装说明；
- `test/package.test.ts` 改为断言可发布 tarball，而不是 `private: true`；
- `prepublishOnly` 跑 typecheck、全量测试、catalog check、package check。

### 平台

- `private: false`、license/description/repository；
- `files` 只含 `src`、`bin`、README/CHANGELOG/LICENSE、设计文档；
- `bin/pigroups.js` 启动 `src/main.ts`；`exports` 暴露 `./package.json`；
- `test/package.test.ts` 检查 tarball、入口和版本；
- 平台版本 `0.7.2`，`src/version.ts` 仍只读 `package.json`。

### 质量门禁

- 两个仓库都加 CI：Node 24（平台当前 engines；22.19 尚未实测，暂不声明支持）、typecheck、全量测试、
  catalog check、package check；
- **常规 CI**：`npm pack` 本地 tarball → 解包检查入口/skills/LICENSE，适配器入口在 node_modules 外 import；
  不访问 registry；
- 适配器 CI 同时 checkout 平台源码，设置 `PIGROUPS_PLATFORM_DIR`；
- **独立 `published-smoke` workflow**：`workflow_dispatch` + 每日 schedule；从 npm 安装真实版本，
  检查依赖、skills、adapter import，并启动平台包回答 `/v1/health`；两个仓库各一个；
- 不允许内部文档、token、test/probe 进入 tarball。

## 5. 发布顺序

1. 平台 `0.7.2`：版本/包元数据/测试/CI → publish → tag `v0.7.2`。
2. 适配器 `0.18.0`：精确依赖 + 平台解析 + 测试/CI → publish → tag `v0.18.0`。
3. `pi install npm:pigroups-adapter-pi` 实机冒烟；确认 `pi.dev/packages` 索引到适配器。
4. 失败则 deprecate/修 patch；不移动已发布 tag。

## 6. 发布验收

- [ ] `npm publish --dry-run` 无 version/repository 自动修正；
- [ ] tarball 不含 handoff/test/probe；
- [ ] 平台包先可安装，适配器精确依赖可解析；
- [ ] 旧平台被四个检查点之一拒绝，新平台 0.7.2 正常；
- [ ] `pi install` tarball 后 extension/skills 可用；
- [ ] `pi.dev/packages` 能检索适配器；
- [ ] 两仓 CI 绿、tag 与版本一致。
