# PiGroups Pi 适配器 设计说明

> 版本：v1.0
> 地位：**《概念稿》是权威**，本文是它的实现伴稿。
> 平台侧的接口契约在 `../PiGroups/docs/设计说明.md` §10。本文只补充适配器自己的契约。

---

## 1. 形态

**一个 Pi 扩展包。** 没有守护进程，没有独立进程，没有旁路服务。装进一个 pi session，那个 session 就是成员。

```
src/
  extension.ts   Pi 扩展入口：注册 pg_* 工具、挂事件、构造 PiSurface
  surface.ts     PiSurface 接口 + pi 的真实实现
  loop.ts        循环：拉取 → 分类 → 注入 → 义务 → 遥测（只依赖 PiSurface）
  herdr.ts       Herdr 接口 + herdr CLI 的真实实现
  pgclient.ts    平台 HTTP 客户端（只用 ../PiGroups/docs/设计说明.md §10 的 15 个端点）
  journal.ts     注入前落盘
  state.ts       义务表、遥测表、合并窗口
```

**`loop.ts` 不许 import `@earendil-works/pi-coding-agent`。** 它只认 `PiSurface`。这是全部可测性的来源。

## 2. 两个接口

### 2.1 PiSurface

```ts
export interface PiSurface {
  /** 把一段文本当成一轮交给 agent。返回时表示已提交，不表示跑完。 */
  deliver(text: string, kind: DeliverKind): Promise<void>;
  /** 切断正在跑的那一轮，并等到空闲。没有在跑就立即返回。 */
  abort(): Promise<void>;
  /** 当前是否有 turn 在跑。 */
  isBusy(): boolean;
  /** 空闲时回调；返回退订函数。 */
  onSettled(cb: () => void): () => void;
  /** 原始事件流：遥测的唯一观测通道。返回退订函数。 */
  onEvent(cb: (e: PiEvent) => void): () => void;
  /** 有序退出这个进程。 */
  shutdown(reason: string): void;
}

export type PiEvent =
  | { type: 'turn_start' }
  | { type: 'turn_end'; error?: { message: string } }   // error 存在 = 这一轮非正常结束
  | { type: 'tool_start'; name: string; argsPreview: string }
  | { type: 'tool_end'; name: string; ok: boolean };

export type DeliverKind = 'message' | 'control' | 'nudge' | 'digest';
```

**`onEvent` 是必需成员，不是可选的。** 少了它，`stalled` 和 `error` 两个遥测态无法推导（概念稿 §5.1 的第一条失败模式就废了）。宁可让没有事件源的面实现在类型上过不去，也不要造一条"遥测悄悄消失"的降级路径——这是本项目一直在猎杀的那类静默失败。

真实实现的映射（按 `pi-coding-agent@1.4.0` 的实际事件名核对过）：

| pi 事件 | `PiEvent` |
|---|---|
| `agent_start` | `{type:'turn_start'}` |
| `tool_execution_start` | `{type:'tool_start', name, argsPreview}` |
| `tool_execution_end` | `{type:'tool_end', name, ok}` |
| `agent_before_settle` 的 `outcome` | `{type:'turn_end', error?:{message}}` —— `completed` 无 error，`aborted` / `error` 带 |

`deliver` → `pi.sendMessage(text, {triggerTurn:true})`；`abort` → 会话的 abort 并等 idle；`shutdown` → `ctx.shutdown()`。

**首次实机要验三件事**，验不过就回来改接口，不要改循环：
1. 在 `agent_settled` 回调里调 `deliver` 能真的起一轮（不是被当成"正在 streaming"拒绝）。
2. 一个正在跑 tool call 的 turn，`abort()` 能切断并等到 idle。
3. `shutdown()` 之后进程干净退出，session 落盘。

### 2.2 Herdr

```ts
export interface Herdr {
  /** 在 workspace 里起一个新 pane 并启动一个 pi。返回 pane 与标签。 */
  spawn(opts: { label: string; env: Record<string,string>; cwd?: string }): Promise<{ pane: string }>;
  /** 等到该 pane 里的 agent 进入 ready/idle。 */
  waitReady(pane: string, timeoutMs: number): Promise<void>;
  /** 读该 pane 的原始文本（只用于诊断与上报）。 */
  read(pane: string, lines: number): Promise<string>;
  /** 关掉 pane。 */
  close(pane: string): Promise<void>;
}
```

真实实现shell 出到 `herdr`：
- 起：`herdr tab create` / `herdr pane split` → `herdr agent start -- pi`
- 等：`herdr agent wait <pane> --state idle --timeout <ms>`
- 读：`herdr agent read <pane>`
- 关：`herdr pane close <pane>`

**未验证的一点**：`herdr agent start` 是否接受环境变量。若不接受，退化为在 pane 里发一行 `PIGROUPS_TOKEN=... pi`（用 `herdr pane send-text`）。这属于 `herdr.ts` 的内部细节，接口不变。

### 2.3 模块对外接口

测试只能通过下面的入口碰到实现，所以它们也是实现必须提供的。**名字和签名照抄，不要另起一套。**

```ts
// src/pgclient.ts
export class PgClient {
  constructor(opts: { url: string; token: string });
}
export class PgGone extends Error {}          // 410 member_gone
export class PgPollBusy extends Error {}      // 409 poll_in_progress
export class PgUnavailable extends Error {}   // 连不上 / 5xx

// src/loop.ts
export interface LoopConfig {
  url: string;
  token: string;
  adapterDir: string;
  pollLimit: number;
  pollWait: number;
  attentionToolMs: number;
  remindWindowMs: number;
  nudgeMax: number;
  spawnCmd: string;
}

export interface InspectResult {
  phase: 'idle' | 'thinking' | 'output' | 'tool_call' | 'unknown';
  busy_ms: number;
  owed: string[];
  children: number;
  tool?: { name: string; elapsed_ms: number; preview: string };
}

export interface ChildSnapshot {
  id: string;
  name: string;
  state: 'ok' | 'stalled' | 'slow_turn' | 'error' | 'idle_owed' | 'gone';
  since: number;
  tool?: { name: string; elapsed_ms: number; preview: string };
  count: number;
}

export class AdapterLoop {
  constructor(deps: {
    pg: PgClient;
    surface: PiSurface;
    herdr: Herdr;
    config: LoopConfig;
    now: () => number;
  });

  /** 启动三个任务（poll / flush / tick）。幂等。 */
  start(): void;
  /** 停止并等待在飞的活干完。 */
  stop(): Promise<void>;

  /** 手动驱动：一次拉取 + 分类 + 派发。测试用；start() 内也是调它。 */
  pollOnce(): Promise<void>;
  /** 手动驱动：把攒下的注入掉（忙则空转）。测试用。 */
  flush(): Promise<void>;
  /** 手动驱动：一次定时器扫描（义务对账、遥测窗口到期、stalled 判定）。测试用。 */
  tick(): void;

  /** 成员工具的实现落点。 */
  say(to: string, text: string, mentions?: string[]): Promise<{ conv: string; seq: number }>;
  spawnMember(opts: { name?: string; brief: string; cwd?: string }): Promise<{ id: string; name: string }>;
  inspect(peer: string, timeoutMs?: number): Promise<InspectResult>;
  children(): ChildSnapshot[];
  state(): { owed: string[]; nudges: Record<string, number> };
}
```

三条约定：

1. **时间只有一个来源。** 所有"过了多久"都用注入的 `now()` 算；`tick()` 的调度用真实 `setInterval`（5 秒），但**判定**只读 `now()`。测试推进假时钟后直接调 `tick()`，不睡。
2. **`start()` 只是把三个任务挂起来**，逻辑都在 `pollOnce` / `flush` / `tick` 里。所以测试可以完全不用 `start()`。

   这一条有个必须遵守的推论：**对 `onSettled` 的订阅发生在构造函数里，不能只在 `start()` 里。** 反应是 `tick()`（同步判定）然后 `flush()`（投递）。把订阅绑在 `start()` 上，等于"不启定时器就收不到空闲事件"，而 §4.3 的催办、§5.2 的 reminder 都挂在这条反应上。

   **一次 settle 最多一次投递，且顺序是 nudge 在前、flush 在后。**

   理由是同一个：`deliver` 只要起了一轮，surface 就进入忙状态，此时再 `deliver` 一次就是在流式过程中插入——pi 的语义是"要么 steer 当前轮、要么排在其后"，不指定会被拒绝。所以：

   ```
   onSettled → tick()（算义务、算遥测窗口）→ nudge（若有，投一条）→ flush()（若还空着）
   ```

   nudge 走在前面的另一个好处是它只针对**本次 flush 之前就存在的**义务：刚被 flush 注入的消息还没机会被回复，不该立刻催。反过来（先 flush 再 nudge）会把这条消息的回复义务在同一瞬间催一遍，白白多一轮。

   **`flush()` 必须可重入安全。** 构造函数订阅后会自己调 `flush()`，调用方（工具、测试、定时任务）也可能同时调。并发调用必须合并成一次——`pending` 用 `splice` 取走的那批不能被另一个并发的 `flush` 重复拼接，闲聊计数也不能被追加两次。
3. **发出消息只能走 `say()`**。它同时维护"欠回复"表——工具层不许绕过它直接 `POST /v1/messages`，否则义务永远不会被清掉。

`src/extension.ts` 只做翻译：`pi.registerTool` → 这些方法，`pi` 事件 → `PiEvent`。

## 3. 循环

三个独立的异步任务，互不阻塞：

```
pollLoop     每轮 GET /poll?wait=25&limit=20 —— 不依赖 isBusy
deliverLoop  只在 !isBusy() 时跑：把攒下的注入掉
timerLoop    每 5 秒：义务复查、遥测窗口到期
```

### 3.1 一轮拉取的处置

```
batch = poll()
journal.append(batch)            // ① 先落盘，再谈注入

for item of batch.items:
  control  → 立即处置（见 3.2）
  message  → 分类（见 3.3）

if !isBusy(): deliverPending()
journal.commit()                 // ② 注入成功才清
```

`journal.commit()` 之前崩溃 → 重启后重放整批。重放可能重复注入，所以注入文本必须带消息号。

### 3.2 控制项

| `cmd` | 处置 |
|---|---|
| `sys.terminated` | 先把 journal 里未注入的丢弃（已经 gone，写了也 410），然后 `shutdown()` |
| `pg.abort` | `abort()`；**不注入任何提示** |
| `pg.steer` | 把 `payload.text` 作为 `control` 类注入；若忙，先 `abort()` |
| `pg.inspect` | 立刻回 `pg.inspect_result`（读当前 phase / 工具 / 义务） |
| `pg.attention` | 只更新上级的遥测表，不注入 |
| 其它未知 `cmd` | 原样注入，标 `kind:'control'`（平台不知道内容，适配器也不该丢） |

**控制项串行处理**，按 `control_seq` 顺序逐条 await。`pg.abort` 之后再来的 `pg.steer` 必须等 abort 完成。

### 3.3 消息分级

只有三档，没有分类器：

| 条件 | 处置 |
|---|---|
| 控制字 | 见 3.2 |
| `mentions_me` 或 `from_parent` 或会话是 `dm:` | **注入**，并置该会话的"欠回复" |
| `gap` 且 `mentioned > 0` | **注入一行**（带锚点），并置该会话的欠回复 |
| `gap` 且 `mentioned == 0` | 不注入，只把 `count` 计入闲聊计数 |
| 其余 | **不注入**，只计数 |

被计数的条数在下一次有注入时附在末尾（`[另有 3 条无关消息]`），否则静默丢弃。**不为闲聊起一轮。**

**`gap` 为什么要分两种。** 平台在成员积压超过 `limit` 时把更旧的消息折叠成一个 `gap`，里面带 `to` / `count` / `before` / `mentioned`。`mentioned == 0` 说明漏掉的都是无关闲聊，把它计进闲聊即可，不值得起一轮；`mentioned > 0` 说明**有直接点名的消息被跳过了**——那正是最不能静默丢的情况，所以给它一行带锚点的提示，并把它算作一次点名：

```
[<to> 跳过了 12 条，其中 2 条点了你的名；用 pg_read(to, before=<before>, limit=20) 回补]
```

两种都要进 journal，重启后一起重放。

注入一条消息时用的文本：

```
[<to>#<seq>] <from_name>: <preview>
```

若 `preview` 被截断（≤200 字符），模型需要全文时自己用 `pg_read`。

### 3.4 注入的合并

一次 `deliver` 里放最多 10 条，按到达顺序。超过则分多次 `deliver`，但要等上一轮结束——否则会排队成十几个 turn。

## 4. 欠回复

### 4.1 判定

某个会话欠回复 ⟺ 该会话的**最后一条**消息不是我发的，且它 `mentions` 包含我 **或** 发送者是我的父。

这就是全部定义。它从句历史直接算出来，所以重启后不需要任何本地状态。

### 4.2 维护

- 每次注入 `message` 后，把该会话标为欠回复（无需查询）。
- 每次 `deliver` 的内容里含"我发了一条消息"时清除。
- **启动时**对 `GET /v1/conversations` 的每个会话做一次 `GET /v1/messages?to=<conv>&limit=1` 全量对账。
- 每次 `agent_settled` 后若表非空，进入 4.3。

### 4.3 催

```
if owed is empty: return
for conv in owed, at most one nudge per conv per settle:
  deliver(`你在 <conv> 还有未回复的消息 (#seq)。回复，或说明为什么不需要回。`, 'nudge')
```

**上限**：同一会话连续催 3 次且期间它没有发出任何消息 → 停止催，改为适配器自发 `pg.report{status:'blocked', text:'no output after N nudges'}` 给父。这条上报不需要模型参与。

`@all` 只产生**一条**义务（一次回复就清掉整个会话），不是每条一个。

## 5. 遥测

### 5.1 下级侧：边沿触发

监视四个状态，**只在进入或离开时报一次**：

| 状态 | 进入条件 | 字段 |
|---|---|---|
| `stalled` | 同一 tool call 持续 > `PG_ATTENTION_TOOL_MS`（默认 300000） | `tool:{name, elapsed_ms, preview}` |
| `slow_turn` | 一轮持续 > 2× 同一阈值 | `busy_ms` |
| `error` | 一轮以 provider 错误结束 | `note` |
| `idle_owed` | idle 且欠回复超过 `PG_ATTENTION_TOOL_MS` | `owed:[conv…]` |

恢复时发 `state:'recovered'`，带 `of:` 原状态名。

上报走控制通道 `pg.attention` 给父。**只发给直接父**，没有父（root）就不发。

### 5.2 上级侧：状态表 + 合并提醒

- 收到 `pg.attention` → 更新 `childId → {state, since, tool, count}`，**不注入**。
- 第一个未处理事件开窗（默认 300000 ms）。
- 窗口到期：
  - 所有子都 `recovered` → **静默取消**，不留痕迹。
  - 否则 `isBusy()` 为真 → 挂起到下一次 `settled`。
  - 否则 `deliver(一条汇总, 'nudge')`。
- 已提醒过的状态不重复提醒，除非（a）之后来了新事件，或（b）同一状态持续超过 1800000 ms（30 分钟）。
- `state:'gone'`（子被删）走**立即**通道，不等窗口。

汇总的文本形态：

```
你的 2 个下级需要处理：
- m_abc（reviewer）stalled 12m 在 bash：find ~/ -name '*.ts'
- m_def（coder）error：provider 429 ×7，最后一次 14:03
```

### 5.3 工具

| 工具 | 谁用 | 行为 |
|---|---|---|
| `pg_children()` | 上级 | 返回遥测表快照（不动模型上下文以外的任何东西） |
| `pg_inspect(member)` | 上级 | 发 `pg.inspect` 并等 `pg.inspect_result`，超时 10 秒 |
| `pg_abort(member?)` | 上级 | 对下级或自己发 `pg.abort` |
| `pg_steer(member, text)` | 上级 | 发 `pg.steer` |
| `pg_say(to, text, mentions?)` | 成员 | 发消息，实现落在 `AdapterLoop.say()`（它顺手清掉义务）|
| `pg_read(conv, before?, limit?)` | 成员 | 读历史，用于 gap 回补或重读简报 |
| `pg_spawn(name?, brief, cwd?)` | 成员 | `POST /members` + 发简报 DM + herdr 起 pane |
| `pg_terminate(member)` | 上级 | `DELETE /members/{id}`（级联） |
| `pg_whoami()` | 成员 | 平台坐标 + 本适配器状态 |

`pg_abort` / `pg_steer` **只接受来自直接父或人的指令**；同群兄弟发来的记一条日志后忽略。这不是权限系统，是"适配器只响应自己的上级"。

## 6. `pg.*` 命令 schema

平台不认识这些，两端靠本文对齐。`v` 用于将来兼容；收到更高版本按未知处理（原样注入）。

```jsonc
// 子 → 父，控制通道
pg.attention   { v:1, child:"m_x", name:"…",
                 state:"stalled"|"slow_turn"|"error"|"idle_owed"|"recovered"|"gone",
                 since:1730000000000, of?:"stalled",
                 tool?:{name:"bash", elapsed_ms:720000, preview:"find ~/ …"},
                 owed?:["g:m_a"], note?:"…" }

// 父 → 子，控制通道；子必须回 pg.inspect_result
pg.inspect     { v:1, request:"r-8f3a" }
pg.inspect_result { v:1, request:"r-8f3a",
                 phase:"idle"|"thinking"|"output"|"tool_call",
                 busy_ms:0, owed:["g:m_a"], children:2,
                 tool?:{name, elapsed_ms, preview} }

// 父或人 → 子
pg.abort       { v:1, reason?:"stalled 12m" }
pg.steer       { v:1, text:"先跑测试再继续" }

// 子 → 父，控制通道；成员的结论
pg.report      { v:1, status:"done"|"progress"|"blocked", text:"…" }
```

`id` 由发送方生成（`crypto.randomUUID()`），重发必须复用同一个，平台按 `(from_id,id)` 幂等。

## 7. 配置

| 变量 | 默认 | 含义 |
|---|---|---|
| `PIGROUPS_URL` | 无 | 平台基址，如 `http://127.0.0.1:7717` |
| `PIGROUPS_TOKEN` | 无 | 本成员 token。**缺失则适配器整体不启用** |
| `PIGROUPS_ADAPTER_DIR` | `~/.pigroups-adapter` | journal 与本地状态 |
| `PIGROUPS_POLL_LIMIT` | 20 | `poll` 的 limit |
| `PIGROUPS_POLL_WAIT` | 25 | 秒 |
| `PIGROUPS_ATTENTION_TOOL_MS` | 300000 | 单次工具调用多久算 stalled |
| `PIGROUPS_REMIND_WINDOW_MS` | 300000 | 上级合并提醒的窗口 |
| `PIGROUPS_NUDGE_MAX` | 3 | 同一会话最多催几次 |
| `PIGROUPS_SPAWN_CMD` | `pi` | 在 pane 里启动什么 |
| `PIGROUPS_PLATFORM_DIR` | `../PiGroups` | **仅测试用**：从哪里拉起平台 |

`PIGROUPS_TOKEN` 缺失时扩展照常加载但不做任何事——同一个扩展装在所有 session 上，只有成员才该开始拉取。

## 8. 启动与退出

**启动序列**（`session_start`）：
1. 读配置；无 token 则停在这里。
2. `GET /v1/whoami` → id / name / parent_id / is_root / groups。
3. 若有父：读 `dm:<me>_<parent>` 的最后一条作为任务简报，注入一次（`kind:'message'`）。
4. 全量对账义务表（§4.2）。
5. 重放 journal 里未注入的批次。
6. 启动三个循环。

**退出**（`session_shutdown` 或收到 `sys.terminated`）：
1. 尽力 `pg.report{status:'blocked', text:'exiting'}` 给父，超时 2 秒即放弃。
2. 停循环。
3. `PgClient` 无连接可关；journal 已提交。

## 9. 错误与上限

| 情况 | 处置 |
|---|---|
| `poll` 409 `poll_in_progress` | 另一个本进程实例在拉；等 `Retry-After` 秒重试，连续 5 次后停 30 秒 |
| `poll` 410 `member_gone` | 停止一切，`shutdown()` |
| `poll` 401 | 停循环，注入一条"token 失效"给 agent，等人工 |
| 平台连接失败 | 指数退避，上限 30 秒；连续 20 次后上报父 `blocked` 并停 |
| 单次 `deliver` 失败 | 保留 journal，等下一次 settle 重试 |
| `pg.inspect` 超时 | 回一张 `phase:'unknown'` 的结果给自己，不编造 |

**不做的重试**：429。Pi 自己会重试，适配器只在"重试用尽且没有产出"时按 §4.3 报 `blocked`。

---

## 10. 测试策略

三条腿，都在 `npm test` 里：

1. **循环对假 PiSurface + 真平台**。测试起来一个真平台进程（`PIGROUPS_PLATFORM_DIR/src/main.ts`，`PORT` 与 `PIGROUPS_DATA` 用临时目录），假 surface 记录每一次 `deliver`/`abort`。断言的是**注入文本与顺序**，不是内部状态。
2. **命令 schema 双向**。发 `pg.inspect` → 断言对端收到 `pg.inspect_result` 且 `request` 对得上；`pg.attention` 四态各一条。
3. **假 Herdr**。`spawn` 断言发出的 herdr 参数、env、cwd；`waitReady` 超时路径。

**不测**：真实 `pi.sendMessage` 是否真能起一轮，真实 herdr 是否真能起 pane。这两件事只能在实机上验（§2.1 的三条）。测试替代品是接口，不是行为——这一点在 §2.1 写明了。
